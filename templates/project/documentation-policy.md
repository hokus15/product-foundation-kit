## Template language

The method's guides, examples, blueprints, and canonical templates are distributed in English. Read them from the external source and generate the initiative's policy at W01. Each project selects its documentation languages independently; remove method-language directions from its generated policy.

## Project language choices

Select a common language or different languages by area when defining the project. Record the intended readers and the reason for each choice. Apply explicit task instructions when they establish a language for the work being requested.

The conversation language is recorded separately in [project conventions](conventions.md). Use the [onboarding guide](../../method/guide.md) to establish language choices through focused questions.

## Applying templates

Write document content, titles, descriptive metadata values, examples, and authoring instructions in the selected language. Translate template headings while preserving their meaning and section structure. Keep existing identifiers, metadata keys, and defined status tokens stable so references remain consistent.

| Naming concern | Selected convention |
| --- | --- |
| Filename and profile slug language | Not selected |
| Glossary terms across documentation languages | Not selected |
| Authoritative language and translation maintenance, if multiple versions exist | Not selected |

Preserve existing filenames and update heading fragments when translated headings change. Define source code naming conventions with the technical profile when implementation is planned.

## Ownership and changes

This document is the reference for documentation language choices. Agent instructions and area guides refer to it. When a choice changes, identify affected documents, links, and translations, and record the remaining adaptation work here.
