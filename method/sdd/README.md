# SDD and execution module

This module continues the kit's [complete route](../workflow.md) from a ready PM handoff through shared specifications, profile planning, implementation, verification, release, and outcome review, up to the selected endpoint.

| Resource | Responsibility |
| --- | --- |
| [Execution guide](workflow.md) | W06–W12 and I01–I04 with inputs, outputs, roles, and completion rules. |
| [Roles](roles.md) | Human and AI hats for specification, architecture, engineering, verification, and operations. |
| [Artifact catalog](artifacts.md) | Canonical schemas, destinations, and creation conditions. |
| [Authoring guide](authoring-guide.md) | Shared behavior, dependency direction, and review criteria. |
| [Product schemas](../../templates/sdd/specs/product/templates/README.md) | Processes, rules, Features, and acceptance. |
| [UI](../../templates/sdd/specs/ui/README.md) and [contracts](../../templates/sdd/specs/contracts/README.md) | Framework-independent experience and transport-independent operations. |
| [Architecture](../../templates/sdd/specs/architecture/README.md) | Profiles, ADRs, enablers, plans, operating guides, and conformance. |

The [PM catalog](../artifacts.md) owns the foundation and early technical records. Canonical profile and ADR schemas also support [technical discovery during PM](../technical-discovery.md).

Preserve the endpoint, mode, increment, intended profile, authoritative definitions, and accepted decisions. Read resources as their work becomes applicable. Keep all schemas and guides external and generate only actual project outputs within scope.

Another SDD tool or process can replace this module through the [handoff rules](../handoff.md). Shared product definition and source ownership remain reusable.
